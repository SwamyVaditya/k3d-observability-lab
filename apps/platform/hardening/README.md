# Platform Hardening - Lab vs Real Prod

> This folder is **portfolio/learning purpose** for `Production Hardening Checklist`.
> In real production, hardening is not an afterthought folder applied on top of running prod.

## What is in this folder (k3d lab)

```
apps/platform/hardening/
├── 01-resource-limits.yaml         # Reference - how limits should look
├── 02-poddisruptionbudgets.yaml    # Applied - PDBs for cart/checkout/frontend/kafka
├── 04-probe-verification.yaml      # Reference - verify liveness/readiness exists
├── hardening.app.yaml              # Argo CD Application (app-of-apps) **Moved to "apps/monitoring" folder**
└── README.md                       # This file
```

### How applied in THIS lab (all workloads in `monitoring` namespace)

```powershell
# 1. Resource Limits - imperative for lab (since otel-demo is OSS)
kubectl -n monitoring set resources deployment cart --requests=cpu=50m,memory=128Mi --limits=cpu=500m,memory=512Mi
kubectl -n monitoring set resources deployment checkout --requests=cpu=50m,memory=128Mi --limits=cpu=500m,memory=512Mi
kubectl -n monitoring set resources deployment frontend --requests=cpu=100m,memory=128Mi --limits=cpu=500m,memory=512Mi
kubectl -n monitoring set resources deployment kafka --requests=cpu=100m,memory=256Mi --limits=cpu=1000m,memory=1Gi

# 2. PDBs - declarative, GitOps managed
kubectl -n monitoring apply -f 02-poddisruptionbudgets.yaml
kubectl -n monitoring get pdb

# 4. Probes - verification only (otel-demo already has /health)
kubectl -n monitoring get deploy cart checkout frontend kafka -o jsonpath='{range .items[*]}{.metadata.name}{" -> liveness: "}{.spec.template.spec.containers[0].livenessProbe.httpGet.path}{" readiness: "}{.spec.template.spec.containers[0].readinessProbe.httpGet.path}{"\n"}{end}'
```

## How it is done in Real-World Production

**Hardening is Day 1, not Day 2.** You don't create a `hardening/` folder after prod is ready.

### Real Prod Structure (App-of-Apps)

```
apps/
├── platform/              # Synced FIRST by root.app.yaml
│   ├── kyverno-policies/
│   │   ├── require-resources.yaml      # Policy: block deploy if limits missing
│   │   ├── require-pdb.yaml            # Policy: block deploy if >1 replica and no PDB
│   │   └── require-probes.yaml
│   ├── pod-security/
│   │   └── pss-restricted.yaml
│   └── cluster-addons/
│       └── ...
├── monitoring/
│   └── prometheus-grafana-values.yaml  # prometheus resources/PDBs are HERE
├── otel-demo/
│   ├── values-prod.yaml                # cart.resources, checkout.pdb are HERE
│   └── otel-demo.app.yaml
└── root.app.yaml
```

### Where each item REALLY lives

| Item | Lab (this repo) | Real Prod (EKS/GKE) |
|------|-----------------|---------------------|
| **Resource Limits** | `01-resource-limits.yaml` + `kubectl set resources` | In Helm `values-prod.yaml`: `cart.resources.limits.memory=512Mi`. Enforced by Kyverno `require-resources` policy. |
| **PDBs** | `02-poddisruptionbudgets.yaml` | In Helm `values-prod.yaml`: `checkout.pdb.minAvailable=1`. Or generated by chart. |
| **NetworkPolicies** | Skipped (flannel) | `platform/network-policies/default-deny.yaml` + Cilium. Enforced by CNI. |
| **Probes** | `04-probe-verification.yaml` | In Deployment chart itself, enforced by Kyverno `require-probes`. |
| **Runbook** | `docs/runbooks/checkout-slo-burning.md` | Same, but linked from Alert `runbook_url` annotation and PagerDuty. |

### Why not patch running prod?

1. **GitOps drift:** `kubectl patch` creates drift from Git. Argo CD will revert it.
2. **OSS app:** You don't edit Deployment of otel-demo (open-source). You override via values.
3. **Policy as Code:** Real hardening = Kyverno/OPA blocks non-compliant manifests at admission, not manual YAML after.

### What this lab demonstrates for resume

> "I implemented production hardening as a dedicated folder to learn PDBs, resource limits, and probes in a k3d lab where all workloads run in `monitoring` namespace. I understand in production EKS, these would be part of Helm values and enforced by Kyverno/OPA policies synced before apps via App-of-Apps, not as post-deploy patches. NetworkPolicies were intentionally skipped because k3d flannel doesn't enforce them."

This shows you know both **how to do it in lab** and **how it's done in prod**.

## Argo CD App-of-Apps Integration

```yaml
# apps/platform/hardening.app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: platform-hardening
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/SwamyVaditya/k3d-observability-lab
    path: apps/platform/hardening
    targetRevision: main
  destination:
    server: https://kubernetes.default.svc
    namespace: monitoring
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```
